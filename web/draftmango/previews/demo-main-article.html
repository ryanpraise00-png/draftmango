Design tokens are a contract, not a colour list

Why we now version tokens the way we version an API, and the three breaking changes that taught us to.

Rafael Montoya Head of Templates
Sep 8, 2026 7 min read
Share

A colour list tells you what exists. A contract tells you what you can rely on. For the first two years of our template system we shipped the former and behaved as if it were the latter, right up until a harmless-looking rename broke four templates on the same afternoon.

Key takeaways

  • Name tokens by purpose, never by the value they hold.
  • Treat a rename as a breaking change, with a version bump.
  • Deprecate first, delete one release later.

In this article

  1. A colour list is a promise nobody signed
  2. Version tokens like an API
  3. Three changes that broke things
  4. How to start on Monday

A colour list is a promise nobody signed

Our first token file was a tidy list of every blue, grey and pink across the catalogue. Designers loved it. Developers copied values out of it. Nobody could say which of those values were safe to change, because nobody had ever written down what each one was for.

So when we nudged blue-600 by a few percent, it quietly changed button text contrast, chart lines and a warning banner: three decisions made by three people who never knew they shared a colour.

Version tokens like an API

The fix was not a new tool. It was a change in attitude. Tokens are an interface other people build on, so they deserve the same care as an API. Every token now has a purpose-based name, the version it appeared in and, when it is on its way out, a deprecation note.

{
  "color.action.primary":       { "value": "{blue.600}", "since": "3.0.0" },
  "color.action.primary-hover": { "value": "{blue.700}", "since": "3.0.0" },
  "color.feedback.warning":     { "value": "{amber.500}", "since": "3.2.0" },
  "color.brand.accent-legacy":  { "value": "{pink.500}", "deprecated": "4.0.0" }
}

With purpose in the name, we can change what blue.600 looks like without touching what color.action.primary means. It is also why every Draftmango template can switch its whole palette from one place: the contract holds even when the colours move.

Three changes that broke things

  1. The rename. primary became brand in a tidy-up, and every page importing the old name fell back to black.
  2. The "small" shift. A grey moved two steps lighter and body text on three landing pages failed contrast.
  3. The deletion. An unused-looking token turned out to style every error state in a checkout.
Tokens are not a design deliverable. They are the part of the design other people build on. Rafael Montoya, Head of Templates

How to start on Monday

You do not need a rewrite. Pick the ten tokens used most across your site, give each a purpose-based alias, and publish the old names as deprecated. Then watch who complains. That list is your real dependency map.

Keep a one-page changelog written for designers, not only for developers. The people who pick colours need to know when a name is going away just as much as the people who import it.
